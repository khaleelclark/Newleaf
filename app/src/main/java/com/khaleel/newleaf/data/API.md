# Newleaf data API

Package: `com.khaleel.newleaf.data`. Shared `EntryKind`, `Entry`, `AppSettings`, `Journal` match the manager contract; optional metadata fields add evidence, canonical amounts, library status, immutable recipe/ingredient snapshots, drink composition and sources.

`Entry.nutrients` always holds consumed-portion nutrition on journal records. `Nutrition.scalePortion` converts a reference basis exactly once. Reference-only FOOD/DRINK records must use `isLibrary=true`. RECIPE/TEMPLATE default to library. Do not put drink composition ingredients into the journal as additional FOOD contributors.

`JournalRepository(context)` exposes `state: StateFlow<Journal>` and suspend `upsert`, `upsertAll`, `delete(Set<String>)`, `saveSettings`, `saveDraft`, `clearDraft`, `restoreJournal(journal, replace)`; `awaitLoaded()` waits for initial durable state, `close()` releases the repository collector; process-wide Room storage remains available to other UI/reminder handles. Room transactions commit before state updates. Upsert STEPS replaces that local date's previous total. `delete` keeps dependents as unlinked observations by default; `deleteWithDependents(ids, cascade)` returns removed and pre-edit dependent/parent snapshots for atomic Undo through `upsertAll`. Drafts are durable private local state. Changed upserts advance record revisions and retain creation time; restore preserves incoming revisions. `error: StateFlow<Throwable?>` reports initial-load errors. `purgeUnreferencedPhotos(minimumAgeMillis, protectedPaths)` removes private photos after the Undo window, default minimum file age 24 hours. It protects all nested journal snapshots, paths in durable JSON drafts, and optional active-draft paths. If a saved draft cannot be parsed, cleanup returns zero. UI should pass active in-memory draft photo paths through protectedPaths while its draft save is pending. Recovery archives contain their own photo bytes and are stored outside the photo cleanup directory. UI owns calling cleanup after Undo expires.

Recipe logging copies `recipeSnapshot` and `recipeVersion`; later library edits cannot recalculate history. Repeat helpers generate new IDs and links. Event timestamps use ISO instants + IANA zone + preserved local date; `EventTimes.at` edits time and recomputes date. For STEPS/NOTE `dateOnly=true`, export omits synthetic event time. `EventTimes.resolve` rejects DST gaps and requires overlap offset selection.

`JournalExports.json(journal, options)`, `markdown(journal, options)`, `csvZip(journal, options, photoReader)`, and `backup(journal, photoReader)` return String/ByteArray. `ExportOptions` supports inclusive `fromDate`/`toDate`, notes, photos, library, recipes. Defaults include notes, exclude photos/library. Photos require bytes from `PhotoReader`; failed/missing attachments fail the operation rather than claim a complete archive. Outputs never include gatewayToken or drafts. JSON schema 1.0 includes named arrays, canonical entries, manifest, attachments and summaries.

`JournalExports.previewRestore(bytes)` validates ZIP digests/schema/references and returns `RestorePreview(journal, attachments, isFullBackup, selectedCount, contextCount, requiredStorageBytes, warnings)`. Commit with repository `restoreArchive(preview, replace, resolutions)`; replace writes a recovery backup before transaction. `repository.restoreConflicts(preview.journal)` reports current conflicts. Merge conflicts need explicit KEEP_EXISTING / USE_INCOMING decisions. Unsupported schemas fail before mutation. UI must show counts/conflicts and choose merge/replace. Photo paths are rewritten into private restored storage, not trusted archive host paths.

Settings gateway credentials are stored using Android Keystore protection, excluded from Room payloads, exports/backups, and recovery backups. Restoring settings keeps current device credentials and, when a device token is configured, its current gateway URL; an imported URL cannot redirect an existing device token.

Domain: `Units` converts mass/volume/body weight/distance without rounding; ambiguous `oz` is mass, never fluid volume. `Nutrition.aggregate` reports sum/count/unknown/estimated/completeness per nutrient; `partialContributors` retains incomplete recipe/composition coverage alongside known sums. `NutrientEvidence.coverageKnown/coverageTotal` records ingredient coverage; partial missingness does not by itself set estimated status, while genuinely estimated ingredients propagate that status. `Summaries.day`, `range`, `weightTrend` preserve missing vs zero and exclude library/meal totals. Water counts `countsAsWater`, not name heuristics. `Recipes.create`, `log`, `repeatMeal` preserve snapshots.

Dependencies owned by app manager: Room runtime + ktx/compiler, Gson 2.11.0, kotlinx.coroutines; JVM tests JUnit 4, instrumentation AndroidX test runner/core/Room testing. All write methods may throw validation/conflict/storage errors; UI should keep the draft and show failure.

## Verification and samples

`python3 app/src/test/java/com/khaleel/newleaf/data/run-isolated-tests.py` runs pure domain/export JUnit tests without compiling UI, using cached Gradle dependencies. Standard build: `./gradlew :app:testDebugUnitTest :app:assembleDebugAndroidTest`. Device checks: `./gradlew :app:connectedDebugAndroidTest` with an emulator/device. `PersistenceTest` covers transaction rollback, delete/Undo, conflicts, photo restore and recovery archives.

Fictional exports are in `app/src/test/resources/data/samples/`: journal.json, journal.md, journal-csv.zip, journal-backup.zip, one-day-context.json and README.md. Regenerate with the isolated runner's `--samples app/src/test/resources/data/samples` option; these fixtures never open the journal database.

Room schema v1 is exported through the manager's KSP configuration. No destructive migration fallback is enabled. Future schema changes must add explicit migrations and migration tests. Byte-returning export APIs deliberately fail if the bounded archive exceeds 256 MiB expanded or an individual attachment exceeds 64 MiB; archives are generated in memory. The current corpus verifies small journals, not the planned one-year device performance target.

## Process-wide Room ownership and OFF subsets

All JournalRepository handles for the same application database path share JournalStorage's single Room connection owner, WAL, serial query/transaction executor and write mutex. Closing a handle cancels its collector only. The database lives for the Android process; UI and alarm receivers can load/write concurrently without opening competing Room instances. Initial-load failures remain visible through awaitLoaded/error. Android's [Room guidance](https://developer.android.com/training/data-storage/room) recommends a singleton database for a single process. The app currently uses one process; a future multi-process service would need explicit multi-instance invalidation and testing.

When selected records or nested snapshots contain Open Food Facts sources, JSON includes source_notices and open_food_facts_nutrition; CSV/full-backup ZIPs additionally include open_food_facts/nutrition.json and open_food_facts/LICENSE.md under the integrity manifest. Markdown carries the linked notice and independently extractable structured subset. The subset contains public provider identifiers and nutrient snapshots, reconstructing reference basis where nutrition_scale is available. It excludes personal names, record IDs, event times, notes/descriptions, photos, weight, drafts, manual drink additions and user override text/values. Canonical journal.json still preserves all user data.

`Nutrition.composeDrink` retains the uncombined base nutrient map and evidence in `drink_base_nutrients` and `drink_base_evidence` metadata. The OFF subset uses only those base keys, values, provider codes and statuses for composed drinks; it never substitutes the combined totals or composition evidence. Legacy composed snapshots without saved base evidence retain their base values without inventing provider codes. Editors must preserve the metadata returned by `composeDrink`, restore base evidence before recomposition, and update `nutrition_scale` when changing the consumed portion.

Subset notice links [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) for database rights and [DbCL 1.0](https://opendatacommons.org/licenses/dbcl/1-0/) for contents, with attribution to Open Food Facts contributors. This scoped notice does not assign these licenses to private journal content or certify unrestricted reuse. Source licensing follows the manager's published-terms decision and [OFF licensing guidance](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/). Other restricted sources still fail save/export visibly; no silent source exclusion.

## Atomic editor save

`suspend fun applyEdits(upserts: List<Entry>, deleteIds: Set<String>): List<Entry>` applies upserts, non-cascading deletion/unlinking and STEPS/NOTE daily-key replacement in one validated Room transaction. It returns all changed/removed original entries, including affected parents/dependents and replaced daily totals. Existing changed entries advance revision once and retain creation time. An ID appearing in both inputs, duplicate upsert IDs, invalid fields or invalid final references fail without committing. Embedded ingredient links and recipe snapshots survive deletion of their library source.

For edits that add no IDs, Undo is `upsertAll(returnedSnapshots)`. If the save creates new IDs, compute `addedIds = upserts.map { it.id }.toSet() - before.entries.map { it.id }.toSet()` and Undo with `applyEdits(returnedSnapshots, addedIds)`; restoring original snapshots alone cannot delete newly created entries. New-entry Undo can call `applyEdits(emptyList(), addedIds)`.

Original `.heif` attachments retain their extension, bytes and `image/heif` manifest MIME in CSV/full backup archives.
