# Nutrition API contract

Current contract for Newleaf 0.1.5, reviewed October 22, 2026. Package `com.khaleel.newleaf.nutrition`. Sources remain separate; no merged nutrient records. [Release evidence](../../../../../../../../releases/VALIDATION.md) records integrated checks.

`NutritionClient(settings: AppSettings)` exposes suspend `search(query): List<FoodCandidate>` (USDA), `barcode(code): FoodCandidate?` (Open Food Facts), `describe(text): List<FoodCandidate>` (free USDA-assisted matching), `details(candidate): FoodCandidate` (USDA selected result), and `status(): GatewayStatus`. All methods throw `NutritionException(category: NutritionError, retryAfterSeconds: Long? = null)` with fixed safe `message` text; barcode returns null only on confirmed no match. No simulated online results. Without a personal USDA key or optional gateway URL/token, USDA calls raise UNCONFIGURED. OFF remains direct/keyless. `/v1/status` reports USDA and free description availability. Nutritionix is absent from the gateway response; the compatibility `GatewayStatus.nutritionix` property is always false/false/`free_only`, even if an older server advertises commercial availability.

FoodCandidate public fields: `name`, `brand: String?`, `quantity: Double?`, `unit: String`, `nutrients: Map<String,Double?>`, `basis: NutrientBasis` (PER_100_G/PER_100_ML/PER_SERVING/CONSUMED/UNKNOWN), `basisQuantity: Double?`, `basisUnit`, `servingMassG: Double?`, `servingVolumeMl: Double?`, `portions: List<PortionDefinition>`, `source`, `sourceId: String?`, `barcode: String?`, `region: String?`, `estimated: Boolean`, `kind: EntryKind`, `originalText`, and `sourceReference`, plus `needsDetails`, `incompleteNutrition`, `matchStatus`, `confidence` (null when absent), `metadata`, `preparation`, `nutrientUnits`, `nutrientProviderCodes`, `estimatedNutrients`. `toEntry(quantity: Double? = this.quantity, unit: String = this.unit, kind: EntryKind = this.kind): Entry` scales into consumed nutrients exactly once. Unsupported conversions preserve unknown nutrients and the input portion; arbitrary drinks never use water density. UI can override drink classification.

Core nutrient keys: energy_kcal, protein_g, carbohydrate_g, fat_g, saturated_fat_g, fiber_g, sugar_g, sodium_mg. Missing remains null. Extra nutrients retain namespaced provider codes and units in Entry.nutrientEvidence; original numeric values/units and derivations are in Entry.metadata. Portion evidence and identity confirmation are separate; description amounts and matches remain estimated until explicit review; metadata preserves parsed versus unspecified quantity, fragment/query and unit recognition. No unspecified quantity becomes 100 g. UNKNOWN candidates have only null nutrients; used for incomplete search summaries or products without nutrition. Details reject unsupported nutrient bases. No numeric confidence is invented.

HTTP protocol (device bearer token, HTTPS, JSON): GET `/v1/status`; GET `/v1/usda/search?query=...`; GET `/v1/usda/foods/{fdcId}`; POST `/v1/describe` with `{ "text": "..." }`. Search/detail responses project used USDA fields; description response is specified below; errors use `{ "error": { "code": "free_only|unconfigured|authentication|access_entitlement|rate_limited|budget_exceeded|invalid_request|not_found|unavailable|malformed_response", "message": "safe text", "retry_after_seconds": null } }`. Status has `usda` and `describe`, each `configured`, `enabled`, `reason`; `describe` also has `mode: "usda_assisted"` and `free_only: true`. Legacy `/v1/parse`, `/v1/nutritionix/describe` and `/v1/nutritionix/parse` always reject with HTTP 403 `free_only` and no commercial network call. Legacy Nutritionix environment credentials cannot activate any route.

Open Food Facts: direct GET `https://world.openfoodfacts.org/api/v3.6/product/{code}.json`, custom `Newleaf/<installed version> (personal Android food journal)` User-Agent. `NutritionClient` accepts an optional `openFoodFactsUserAgent` constructor parameter for the owner's chosen contact URL/email; no contact identity is invented in the default. Add owner contact before broader distribution. Digits-only GTIN-8/12/13/14 with checksum, exact returned identifier required (zero padding equivalence permitted); no keyword fallback. Endpoint pin checked in official docs October 1, 2026. No auto POST retries, no shared/deployed provider secrets on phone or any keys in exported Entry; device token storage belongs to secure local settings, excluded from backup/export.

OFF nutrients come from one selected as-sold manufacturer/packaging input set. Supported nutrient-bearing sets are preferred over metadata-only (for example NOVA-only) sets; manufacturer preference still applies among nutrient-bearing candidates. NOVA in a selected set is retained as original classification metadata, never scaled as a nutrient. A companion as-sold serving set from that same origin can supply its declared mass or volume for `toEntry(..., "serving")`; its nutrient values are ignored. Conflicting same-origin serving definitions leave serving conversion unknown. No serving portions are inferred from another origin, aggregate nutrition, or arbitrary density. Barcode fields also request quantity/product_quantity/product_quantity_unit. A positive finite normalized whole-package measurement with explicit g/ml unit becomes PortionDefinition("package", 1, mass/volume). Original quantity text is retained in off_package_label; no text size parsing or inference occurs. Multipacks represent the complete outer package. Missing/invalid/unsupported package measurements supply no package conversion. FoodCandidate.convertAmount converts explicit package/serving/measured quantities without arbitrary density. UI percentages divide by 100 once before toEntry; saved quantities use fractional package units and consumed nutrients.

Barcode UI handoff: `barcode(scannedDigits)` already performs the keyless lookup; a non-null candidate is a recognized product ready for **prefilled product/portion review**, with name, brand, source/barcode and safely available nutrition. Callers should open that review immediately after capture, preserving the draft, and require explicit confirmation before adding/saving. `details(candidate)` returns OFF candidates unchanged; no USDA request is needed. A null result means HTTP 404 or a v3 `failure` whose result ID is a supported product-not-found spelling. Other HTTP errors (including 429/503), unrelated failure envelopes, identity mismatch and malformed selected nutrient rows throw a sanitized `NutritionException`; callers must distinguish those from no match, show the error/manual path and clear stale prior results. No automatic retries or provider fallback occur, and only User-Agent/Accept headers go to OFF even when both USDA and gateway credentials are configured.

A recognized product with missing/unsupported nutrition input sets now remains available for review: UNKNOWN basis, null quantity, `serving` unit label, null nutrients, no serving conversion (an independently reported whole-package size can still be retained) and `incompleteNutrition=true`. This label supplies no default amount or conversion. `off_nutrition_status` is `missing_input_sets`, `unsupported_input_sets`, or `supported_input_set`; the UI can explain that product identity was found while nutrition is unavailable. Unsupported bases, prepared-only/estimated-only sets and aggregate-only data are never substituted. A supported later input set may still be selected. Product identity remains reviewable independently of nutrition availability. Physical camera/network behavior and catalog coverage require phone acceptance; use the current release evidence for test totals.

`SourceReference` records snapshots/exports as permitted for USDA CC0. The Nutritionix normalizer remains available only for historical import fixtures; active clients never call its API and no new commercial rights are inferred. Open Food Facts snapshot/export flags are true under its published ODbL-1.0 database and DbCL-1.0 contents licenses. SourceReference retains attribution, database URL and both license URIs. The export contract requires preserving these notices and independently licensing the OFF-derived nutrition subset without applying those terms to private journal notes/photos/body measurements/activity. The data/export implementation emits this subset and notices in JSON, Markdown and CSV/backup archives, with privacy and integrity regressions documented in the data API. This policy covers personal journal retention/export and does not certify unrestricted public catalog redistribution. [Provider rights notes](../../../../../../../../gateway/PROVIDERS_AND_RIGHTS.md) document the published-license policy and the free-only commercial-route prohibition.


## Free description protocol

Input is the exact original `text` (2–2,000 characters), comma/newline-separated with up to eight nonempty items. Optional leading numeric/word quantities, mixed fractions and common Unicode fractions, plus mass/volume/source portion labels are supported. Every query is bounded to 2–200 characters before network fan-out. Response:

```json
{
  "mode": "usda_assisted",
  "original_text": "1/2 cup beans, unmatched",
  "review_required": true,
  "foods": [
    {
      "input_text": "1/2 cup beans", "query": "beans",
      "quantity_hint": 0.5, "unit_hint": "cup", "unit_recognized": true,
      "quantity_estimated": true, "match_estimated": true,
      "match_status": "provisional", "needs_details": false,
      "food": {"fdcId": 123, "description": "Beans", "dataType": "Survey (FNDDS)", "foodNutrients": [], "foodPortions": []}
    },
    {
      "input_text": "unmatched", "query": "unmatched",
      "quantity_hint": null, "unit_hint": "serving", "unit_recognized": true,
      "quantity_estimated": true, "match_estimated": true,
      "match_status": "no_match", "needs_details": false, "food": null
    }
  ]
}
```

Array order and count must match input items; unmatched items are never excluded. `food` maps through the existing USDA mapper. `ProviderMappers.usdaDescription` applies provisional hints and preserves full original text plus the item fragment in `description_item_input`. Matching candidates have USDA IDs and `matchStatus=unreviewed`; unmatched candidates have no source ID, `matchStatus=no_match`, UNKNOWN basis and only null nutrients. All candidates require review and carry `estimated=true`; no confidence is invented. Unknown units preserve their hint and all search words, require review, and cannot imply density or food mass. USDA-supplied portion gram weights support conversions; quantity-prefixed descriptions such as `1 cup` are normalized only when the prefix agrees with the provider's explicit amount.

`details(candidate)` returns a fully detailed description candidate unchanged, preventing duplicate review calls. A fallback search summary may fetch detail once and retains quantity/unit/original input/review metadata. Its freshly mapped nutrient metadata replaces old provider values. `details(fdcId)` remains a raw reference lookup. Each Describe uses up to eight USDA search + eight detail GET calls under shared auth/quota/cooldown/concurrency bounds; no upstream or client POST retries. Description response read timeout is 60 seconds, others 12; every `NutritionRequest` defaults to 12 seconds and clamps custom timeout to 1–60 seconds. These are socket timeouts; a proxy must provide total deadlines. No accounts, commercial calls, paid hosting or AI services are required by this implementation.


## Direct personal USDA access (primary)

`AppSettings.usdaApiKey: String = ""` is the credential contract. A nonblank personal key takes precedence over the optional gateway for `search`, `details`, `describe` and `status`. There is no automatic gateway fallback on direct authentication/network/parse failure, and no retries. Invalid non-printable/whitespace or over-256-character keys fail locally. UI/data owners provision the user's personal key through masked Settings and a distinct Android Keystore vault, excluding it from Room settings, exports/backups and preserving it across restore; the nutrition client never writes credential storage.

USDA requests are GET only to fixed `https://api.nal.usda.gov/fdc/v1/` paths: `foods/search?query=...&pageSize=20`, `food/{fdcId}`, and description search `foods/search?query=...&pageSize=5&dataType=Survey+%28FNDDS%29`. The key is supplied solely in the `X-Api-Key` header, with no key query parameter or gateway Authorization/device token. Header values and request bodies are absent from request diagnostics. OFF requests never receive the USDA key. Shared/deployed API keys remain server-only; this mode uses the owner's personal key on their own device.

Direct `status()` reports local configuration without a network request; configured/enabled means the field is present/valid, not that live credentials/coverage were verified. Nutritionix stays disabled. `MealDescriptionParser` validates every bounded item before network calls and shares the gateway's item/envelope semantics. Up to eight ordered candidates are produced by parallel USDA searches/details, with no-match placeholders and mandatory review. Unspecified portions remain null; no default 100 g or guessed density. `details(candidate)` preserves the same hints/metadata in direct and gateway modes.

One process-wide `UsdaDirectPolicy` bounds all client instances to four concurrent USDA requests, 30 actions/minute and 100 upstream calls/hour; failed/unknown outcomes are not refunded and provider 429 applies Retry-After cooldown. Cancellation releases request slots and disconnects active I/O. These local counters reset with the app process and are **not** the optional gateway's durable quota file. USDA still enforces its own account/IP limits. Each direct GET has an 8-second connect / 12-second read socket timeout; full description fan-out may take longer, with no automatic repeats. The key remains in header memory only during the request. No hosting, account creation, paid API or paid service is performed or required by this client implementation; obtaining a free personal key is the owner's explicit action via the official USDA registration link.


USDA real-response regression: public Foundation detail1750340 declares `1 RACC = 140 g`; this is a named source portion, not one apple or an implicit serving. Its explicit per100g nutrient basis remains independent from that portion. The mapper preserves missing nutrients/amounts and zero values. Authentication failure text is source-neutral: “Nutrition authentication failed. Check your USDA key or gateway token.” All upstream bodies and credentials remain absent from errors.
