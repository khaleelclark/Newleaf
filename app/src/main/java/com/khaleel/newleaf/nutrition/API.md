# Nutrition API contract

Package `com.khaleel.newleaf.nutrition`. Sources remain separate; no merged nutrient records.

`NutritionClient(settings: AppSettings)` exposes suspend `search(query): List<FoodCandidate>` (USDA), `barcode(code): FoodCandidate?` (Open Food Facts), `describe(text): List<FoodCandidate>` (Nutritionix), `details(candidate): FoodCandidate` (USDA selected result), and `status(): GatewayStatus`. All methods throw `NutritionException(category: NutritionError, retryAfterSeconds: Long? = null)` with fixed safe `message` text; barcode returns null only on confirmed no match. No simulated online results. Empty gateway URL/token raises UNCONFIGURED. `/v1/status` reports keyed provider configuration; Nutritionix is unavailable until server account export/retention rights are explicitly enabled.

FoodCandidate public fields: `name`, `brand: String?`, `quantity: Double?`, `unit: String`, `nutrients: Map<String,Double?>`, `basis: NutrientBasis` (PER_100_G/PER_100_ML/PER_SERVING/CONSUMED/UNKNOWN), `basisQuantity: Double?`, `basisUnit`, `servingMassG: Double?`, `servingVolumeMl: Double?`, `portions: List<PortionDefinition>`, `source`, `sourceId: String?`, `barcode: String?`, `region: String?`, `estimated: Boolean`, `kind: EntryKind`, `originalText`, and `sourceReference`, plus `needsDetails`, `incompleteNutrition`, `matchStatus`, `confidence` (null when absent), `metadata`, `preparation`, `nutrientUnits`, `nutrientProviderCodes`, `estimatedNutrients`. `toEntry(quantity: Double? = this.quantity, unit: String = this.unit, kind: EntryKind = this.kind): Entry` scales into consumed nutrients exactly once. Unsupported conversions preserve unknown nutrients and the input portion; arbitrary drinks never use water density. UI can override drink classification.

Core nutrient keys: energy_kcal, protein_g, carbohydrate_g, fat_g, saturated_fat_g, fiber_g, sugar_g, sodium_mg. Missing remains null. Extra nutrients retain namespaced provider codes and units in Entry.nutrientEvidence; original numeric values/units and derivations are in Entry.metadata. Portion evidence and identity confirmation are separate; parser amounts remain estimated because the endpoint does not report supplied-versus-inferred evidence. UNKNOWN candidates have only null nutrients; used for incomplete search summaries or products without nutrition. Details reject unsupported nutrient bases. No numeric confidence is invented.

HTTP protocol (device bearer token, HTTPS, JSON): GET `/v1/status`; GET `/v1/usda/search?query=...`; GET `/v1/usda/foods/{fdcId}`; POST `/v1/nutritionix/describe` with `{ "text": "..." }`. Search/detail/describe responses project used fields from provider schemas; errors use `{ "error": { "code": "unconfigured|authentication|access_entitlement|rate_limited|budget_exceeded|invalid_request|not_found|unavailable|malformed_response", "message": "safe text", "retry_after_seconds": null } }`. Status has `usda` and `nutritionix`, each `configured`, `enabled`, `reason`.

Open Food Facts: direct GET `https://world.openfoodfacts.org/api/v3.6/product/{code}.json`, custom `Newleaf/0.1.0 (personal Android food journal)` User-Agent. `NutritionClient` accepts an optional `openFoodFactsUserAgent` constructor parameter for the owner's chosen contact URL/email; no contact identity is invented in the default. Add owner contact before broader distribution. Digits-only GTIN-8/12/13/14 with checksum, exact returned identifier required (zero padding equivalence permitted); no keyword fallback. Endpoint pin checked in official docs October 1, 2026. No auto POST retries, no provider secrets on phone or in exported Entry; device token storage belongs to secure local settings, excluded from backup/export.

OFF nutrients come from one selected as-sold manufacturer/packaging input set. A companion as-sold serving set from that same origin can supply its declared mass or volume for `toEntry(..., "serving")`; its nutrient values are ignored. Conflicting same-origin serving definitions leave serving conversion unknown. No portions are inferred from another origin, aggregate nutrition, or arbitrary density.

`SourceReference` records snapshots/exports as permitted for USDA CC0. Nutritionix permission depends on explicit server rights confirmation. Open Food Facts snapshot/export flags are true under its published ODbL-1.0 database and DbCL-1.0 contents licenses. SourceReference retains attribution, database URL and both license URIs. The export contract requires preserving these notices and independently licensing the OFF-derived nutrition subset without applying those terms to private journal notes/photos/body measurements/activity. Data/export owns that subset implementation; its completion must be verified independently of the adapter. This policy covers personal journal retention/export and does not certify unrestricted public catalog redistribution. [Provider rights notes](../../../../../../../../gateway/PROVIDERS_AND_RIGHTS.md) document the published-license policy and the unresolved Nutritionix account gate.
