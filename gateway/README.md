# Newleaf nutrition gateway

Implemented in Python standard library; no deployment, provider registration, subscriptions, payments or real provider credentials were used. Run from the Newleaf root with Python 3.11+ on Linux/Unix (uses `fcntl` for the exclusive quota-file lock):

```sh
python3 -m unittest discover -s gateway/tests -v
# Set environment variables privately, using gateway/.env.example as the field list.
# The server deliberately does not auto-load an .env file.
python3 gateway/server.py
```

The server refuses startup without a non-whitespace device bearer token of at least 32 characters. Generate a unique token privately, provision it in the app's local settings, and rotate it by replacing the server token and then the phone token. Never place USDA or Nutritionix keys in Android. Empty provider keys are supported: authenticated `GET /v1/status` and lookup errors clearly report unconfigured. Nutritionix additionally requires `NUTRITIONIX_RIGHTS_CONFIRMED=true` and a positive `NUTRITIONIX_DAILY_LIMIT`. That flag records an operator decision; it does not prove a license.

The listener binds only `127.0.0.1:8787`. Phone access requires a separately configured HTTPS reverse proxy with a valid certificate, preserving `/v1/` paths and Authorization. The Android client accepts only an HTTPS root gateway URL, without user info, path, query or fragment. Do not expose the Python listener publicly. No hosting, TLS service, reverse proxy or device credential has been provisioned as part of this work. The proxy must enforce header/body/time bounds and disable access logs containing queries, Authorization or bodies. Do not enable HTTP request retries for the describe route. Verify this after configuring hosting; those external controls are not installed here.

Routes and JSON/error formats are specified in [the Android API](../app/src/main/java/com/khaleel/newleaf/nutrition/API.md). Only authenticated GET status, USDA GET search/details, and explicit Nutritionix POST describe are available. No arbitrary URLs, provider keys, provider parameters, diary uploads, body weight, feelings, activity, photos, exports or database operations are accepted. Only query/ID/explicit description leaves the phone. A description may itself contain personal text; the first-use UI must explain the recipient. Nothing here promises the provider retains no data.

Search is limited to 2–200 characters and 20 results; describe to 2–2,000 characters and 100 results. HTTP body limit is 8 KiB, upstream response limit 2 MiB. The gateway has a 10-second upstream socket timeout, a 15-second client socket timeout, four concurrent upstream slots, eight HTTP handler slots, and 30 authenticated requests/minute by default. These socket timeouts are not a strict total duration against trickle traffic; a TLS proxy must supply total request deadlines. Provider calls are single attempts and redirects are rejected. Nutritionix sends `num_servings=1`; its returned nutrient values already represent each returned consumed quantity. Duplicate concurrent descriptions are suppressed by an in-memory hash that is removed after the call. A subsequent explicit user action can call the provider again and may be billed. Phone cancellation closes mobile I/O, but an upstream gateway/provider operation may already be underway and can still finish or incur a charge.

USDA's default local ceiling is 100 requests/hour. Nutritionix defaults to zero calls/day until an account-specific request ceiling is deliberately chosen. These are request budgets, not price or billing guarantees. Reserve quota before upstream calls and never refund an unknown outcome. Counters persist atomically to `NEWLEAF_QUOTA_FILE` (mode 0600); the adjacent exclusive lock prevents two gateway processes sharing that file. Preserve this file across restarts and use one gateway instance. Deleting it, deploying multiple instances with separate files, changing limits, or a bad server clock defeats the local ceiling. A corrupt/unwritable quota file fails closed. A provider 429 puts that provider in a local Retry-After cooldown; no automatic retries occur.

No catalog, journal or description payload is cached or stored by the gateway. Its quota state contains only provider/window/count. The Python handler suppresses access logs and returns fixed error messages, never raw exception text, upstream URLs or response bodies. Provider responses are projected to the adapter's used food/nutrient/portion fields; other fields, images, diagnostics and query echoes are removed. Local Python crash/debug tooling and proxy/hosting telemetry remain operator responsibilities. No CORS headers are emitted because the consumer is native Android.

Fixtures use invented nutrient values, fake HTTP transports, and placeholder tokens/keys. They do not validate coverage, production TLS, provider authentication, prices, actual account entitlements or commercial charges.
