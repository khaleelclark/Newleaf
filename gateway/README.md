# Newleaf free nutrition gateway

The gateway uses Python 3.11+ standard library on Linux/Unix (`fcntl` quota-file lock). USDA search, selected details and USDA-assisted meal descriptions are the only upstream capabilities. Open Food Facts barcode reads go directly from Android and require no API key. Nutritionix and every commercial route are disabled even when old credentials or enable flags exist. Nothing was registered, purchased or deployed.

The primary Android path needs **no hosting**: enter your existing free personal USDA key in Settings; Android calls official USDA directly with the key in `X-Api-Key`, held in the data owner's Keystore vault and excluded from exports. Direct status reports configuration, not verified credentials. This gateway is an optional advanced alternative for a server-owned/shared key. You can self-host it on an existing machine; a paid hosting service is not required. Use an **already available free USDA key**, a private device token and a secure HTTPS path to that machine. This work does not create any accounts or subscribe to any service. Empty USDA keys leave manual entry and direct OFF available and report USDA/Describe as unconfigured.

From the Newleaf root:

```sh
python3 -m unittest discover -s gateway/tests -v
# Set private environment variables listed in gateway/.env.example.
# The server deliberately does not auto-load an .env file.
python3 gateway/server.py
```

`NEWLEAF_DEVICE_TOKEN` must be non-whitespace printable ASCII with at least 32 characters. Provision a unique private token in the phone's local settings, and rotate it by changing both ends. `USDA_API_KEY` for this optional gateway stays exclusively on the server and goes to official USDA only in the X-Api-Key header, never in URL parameters; the primary Android personal-key setting is separate. Legacy `NUTRITIONIX_*` environment variables are ignored.

The listener binds only `127.0.0.1:8787`. Phone access requires an HTTPS reverse proxy with a valid certificate, preserving `/v1/` and Authorization. The client accepts only an HTTPS root gateway URL without user info, path, query or fragment. No TLS/proxy/device credentials are provisioned here. Configure proxy header/body/time bounds and disable access logs containing queries, Authorization or bodies. Do not enable automatic retries for description requests. Existing machine/network infrastructure may be used; no paid service is a software dependency.

Authenticated routes: GET `/v1/status`, GET `/v1/usda/search?query=...`, GET `/v1/usda/foods/{fdcId}`, POST `/v1/describe` with `{"text":"1/2 cup rice, 100g chicken\n2 fl oz milk"}`. `/v1/parse`, `/v1/nutritionix/describe` and `/v1/nutritionix/parse` return HTTP 403 `free_only` and make zero upstream calls. Status advertises USDA and `describe.mode=usda_assisted`, with `free_only=true`; Nutritionix is absent. See [the client protocol](../app/src/main/java/com/khaleel/newleaf/nutrition/API.md).

Describe is a small syntax parser: split on commas/newlines, ignore empty separators, accept 1–8 nonempty items and 2–2,000 total characters. Numeric quantities, fractions (`1/2`, `1 1/2`), common Unicode fractions and words one–eight/half are accepted. Quantities must be positive and at most 1,000,000. Recognized units include mass, volume and source-specific cup/tablespoon/teaspoon/serving/slice/piece labels; a recognized label alone does **not** provide a gram conversion. For an unknown leading unit word, the hint is retained and all remaining words stay in the USDA query because the word might instead describe the food. Ambiguous text, conjunctions, recipes and commas within food names require editing/review; this is not a general natural-language or AI service.

Each item uses one USDA GET search (five Survey/FNDDS results for generic prepared foods), then at most one GET detail for the first provisional match. All items remain in order, including `food:null`/`no_match` placeholders. Search/detail identity must agree. A missing detail returns the projected search summary with `needs_details=true`; other provider failures return a safe error for the whole action. Full original input, item text, quantity/unit hints and estimated/review flags are returned. No quantity defaults to 100 g, no portion weight/density is invented, no source nutrients are combined, and no journal entry is auto-saved. Android exposes unmatched editable candidates with unknown nutrients. The normal USDA Search route remains available to find a better match or a branded product.

Maximum fan-out is 16 USDA GET calls per description. Four item workers share **four global upstream slots** with search/details routes. All calls pass through the same persisted hourly quota and Retry-After cooldown. Default local ceiling is 100 USDA calls/hour; it is a request ceiling, not a paid allowance. Reserve before each call and never refund unknown outcomes; there are no upstream retries. Counters persist atomically in `NEWLEAF_QUOTA_FILE` (0600). Preserve this file across restarts; an exclusive adjacent lock prevents two processes sharing it. Corrupt/unwritable state fails closed. Multiple instances with separate files, deleting state or a bad clock defeats this local ceiling.

Search accepts 2–200 characters and 20 results. Describe validates all query bounds before making any call. HTTP bodies are limited to 8 KiB and upstream JSON to 2 MiB. Gateway bounds: default 10-second upstream socket timeout, 15-second client input timeout, four concurrent action slots, eight handler slots and 30 authenticated requests/minute. The Android description response read timeout is 60 seconds (other calls 12 seconds); cancellation disconnects phone I/O but already-started free upstream work may finish. Socket limits are not strict total deadlines against trickle traffic; the HTTPS proxy must apply total request deadlines.

The gateway stores no description, catalog, journal or raw response cache. Quota state contains provider/window/count only. Handler logs are suppressed, fixed error text replaces raw exceptions/URLs, and responses project only adapter fields, without keys, images or diagnostics. No CORS is emitted. Only explicit search terms/item descriptions/IDs leave the phone; descriptions may contain personal text and USDA/provider infrastructure retention is not certified. Exports, photos, body measurements, feelings and diary databases are never sent by this gateway.

Fixtures use invented nutrition and placeholder credentials. See [provider notes](PROVIDERS_AND_RIGHTS.md) and [verification evidence](VERIFICATION.md). New Android direct/gateway fixtures await parent-owned Gradle execution. Optional gateway source/tests also verify header-only upstream keys.
