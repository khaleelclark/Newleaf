# Provider mappings, published licenses and commercial account rights

Official documentation checked October 1, 2026. No account was registered, subscribed, paid for or deployed. Provider credentials have not been used. This is an implementation decision record, not a legal certification.

- USDA: [API guide](https://fdc.nal.usda.gov/api-guide/) documents authenticated search/details, key privacy, the default 1,000/hour/IP limit and CC0/public-domain data. [Branded documentation](https://fdc.nal.usda.gov/GBFPD_Documentation/) explicitly defines either 100 g or 100 mL according to submitted serving units, and distinguishes missing from zero. Non-branded supported datasets use per-100-g; branded data requires an explicit mass or volume serving unit. Incomplete search summaries carry UNKNOWN/null normalization and request selected details; details with unknown basis are rejected. Source item IDs are `usda:{fdcId}`. Core mapping uses USDA nutrient IDs; units are checked, and extra nutrients retain provider ID/unit. Energy can use explicit kJ or Atwater energy nutrient values when kcal is missing; no calories are invented from macro totals. FoodData Central attribution accompanies snapshots/exports.

- Open Food Facts: [current introduction](https://openfoodfacts.github.io/openfoodfacts-server/api/) identifies v3.6 as current and v2 as deprecated, requires an identifying User-Agent and states separate reuse licenses. The truthful default is Newleaf/0.1.0 (personal Android food journal); a constructor override supports the owner's chosen contact URL/email, which is still unprovided and should be added before broader distribution. The introduction lists product read limit 100/minute (per IP for server calls, per user for direct mobile calls); Newleaf performs one explicit read per action, with duplicate in-flight suppression. [v3 API schema](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/docs/api/ref/api-v3.yaml), [nutrition v3 schema](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/docs/api/ref/schemas/product_nutrition_v3.yaml), and [nutrient values schema](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/docs/api/ref/schemas/nutrient_values_v3_base.yaml) describe the new nutrition `input_sets`, explicit `per` (100g/100ml/serving), preparation, units and values. The implementation pins `/api/v3.6/product/{code}.json` and selects ONE as-sold manufacturer set, then packaging; it deliberately ignores `aggregated_set` because that combines sources. No legacy flat-nutriments fallback and no guessed liquid basis. No packaging/manufacturer set or unknown basis with nutrition yields unsupported data; a product with no nutrition can still provide an exact identity with unknown nutrients. Source IDs are `openfoodfacts:{barcode}`; GTIN check digit plus exact/zero-padded equivalence protects product identity. This supports GTIN-8/12/13/14, not arbitrary internal store codes or UPC-E. HTTP 404/explicit product-not-found is a true no-match; no keyword fallback. Source region comes from provider country tags, never from phone locale. No product images are fetched. Nutrient comparisons (<, > etc.) are not treated as exact numeric values. Salt/sodium conversion (salt/2.5) and available carbohydrate+fiber total are marked derived and preserve original provider fields. `value_computed` is not silently substituted for supplied nutrition.

- Nutritionix: [official natural nutrients documentation](https://docx.syndigo.com/developers/docs/natural-language-for-nutrients) specifies `POST https://trackapi.nutritionix.com/v2/natural/nutrients` and x-app-id/x-app-key authentication. Returned `nf_*` and full_nutrients are for the returned serving_qty/serving_unit consumed amount (num_servings kept 1). Rescaling divides by the original quantity exactly once or uses its actual returned total gram weight. Unknown cup-to-volume or gram-to-volume relationships remain unknown. Core mappings preserve units; known extra attribute units use the [official nutrient dictionary](https://docx.syndigo.com/developers/docs/nutrient-attribute-dictionary). Unrecognized attr IDs remain namespaced with provider-defined units instead of falsely choosing a unit. Entire original description is retained locally, labeled as full input because per-item input fragments and supplied-versus-inferred portion evidence are not returned by the selected endpoint. Amounts remain estimated; no numeric confidence or region is invented. Suggested provider event times are discarded so the user's app-selected timestamp wins. Drink classification is an editable suggestion, not an identity guarantee. Subrecipes are not requested, avoiding double counting. One POST attempt only; user retry may incur another charge.

USDA snapshot/export flags are true based on its published CC0 release. Nutritionix snapshot/export flags are true only for results obtainable after the SERVER operator's explicit rights gate; no entitlement is inferred from merely having credentials. Before enabling, document account permission for historical snapshots, favorites, recipes, offline copies, identifiers/derivatives, CSV/JSON/Markdown, full backups, and user-directed AI analysis; also confirm quotas/prices/retention and attribution for the chosen account. Public endpoint documentation does not grant these permissions. Nutritionix is a proposed provider for the required commercial category; no fatsecret substitution was implemented.

Open Food Facts personal-journal policy uses its [published licensing guidance](https://openfoodfacts.github.io/openfoodfacts-server/api/tutorials/license-be-on-the-legal-side/), [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/) and [DbCL 1.0](https://opendatacommons.org/licenses/dbcl/1-0/). ODbL permits temporary/permanent copying and derivatives subject to its conditions; notices/license URIs and share-alike/access requirements apply when conveying or publicly using covered data. DbCL grants content reuse subject to ODbL. On that published basis, the adapter now sets snapshotAllowed/exportAllowed=true, preserving attribution, database URL, both full license URIs and derivation evidence. No unspecified owner-review checkbox disables personal logging or export.

Exports must preserve source notices in JSON/Markdown/CSV/backups and provide an independent machine-readable OFF-derived nutrition subset under ODbL/DbCL, without private journal notes, photos, body measurements or activity. Personal material is separate collective content and is not automatically relicensed under OFF terms. This is the manager-selected implementation policy, not a certification that every redistribution use is unrestricted. Product images have separate rights and are not fetched. Broad public catalogs or new distribution/combination uses require evaluating the applicable license obligations separately. Data/export owns the subset/archive implementation and its integration tests; nutrition owns these source notices and permitted snapshot flags.

No network credential, raw provider response cache, image or provider interpreted timestamp enters Entry. Original mapped numeric values/units, source references, basis, conversions, missingness, estimation and region are preserved in consumed snapshots. Sources never fill each other's nutrient gaps. Catalog refresh does not mutate any historical journal record. If provider rights cannot support Newleaf's required complete portable history, resolve that provider choice with the owner before claiming a complete release.
